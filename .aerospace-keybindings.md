# Keybindings — macOS (AeroSpace)

Mirrors `~/.config/i3/config` from EndeavourOS so muscle memory carries over.

`mod` = **Option (⌥)**. Option sits in the same physical slot as the winkey on a
PC layout, which is why it stands in for i3's `Mod4` rather than Command.

Source of truth: `~/.aerospace.toml` and `setup_macos_hotkeys()` in
`~/.dotfiles/.mac-setup.sh`.

## Windows

| Keys | Action | i3 |
|---|---|---|
| `⌥ Enter` | open Ghostty | `$mod+Return` |
| `⌥ q` | close window | `$mod+q` |
| `⌥ h` `⌥ j` `⌥ k` `⌥ l` | focus left/down/up/right | `$mod+h/j/k/l` |
| `⌥ ←` `⌥ ↓` `⌥ ↑` `⌥ →` | focus left/down/up/right | `$mod+arrows` |
| `Ctrl ⇧ h/j/k/l` | focus left/down/up/right | `Control+Shift+h/j/k/l` |
| `⌥ ⇧ h` `⌥ ⇧ j` `⌥ ⇧ k` `⌥ ⇧ l` | move window | `$mod+Shift+h/j/k/l` |
| `⌥ ⇧ ←` `⌥ ⇧ ↓` `⌥ ⇧ ↑` `⌥ ⇧ →` | move window | `$mod+Shift+arrows` |
| `⌥ ⇧ f` | fullscreen | `$mod+Shift+f` |
| `⌥ ⇧ Space` | floating toggle | `$mod+Shift+space` |

Focus wraps at the workspace edge, matching i3's default.

## Workspaces

| Keys | Action | i3 |
|---|---|---|
| `⌥ 1` … `⌥ 9`, `⌥ 0` | go to workspace 1-10 | `$mod+1..0` |
| `⌥ ⇧ 1` … `⌥ ⇧ 9`, `⌥ ⇧ 0` | move window to workspace 1-10 | `$mod+Shift+1..0` |
| `⌥ Tab` | next workspace | `$mod+Tab` |
| `⌥ ⇧ Tab` | previous workspace | `$mod+Shift+Tab` |

## Resize mode

`⌥ r` enters resize mode. Then:

| Keys | Action |
|---|---|
| `h` / `l` | width -50 / +50 |
| `k` / `j` | height -50 / +50 |
| `Enter` or `Esc` | back to main mode |

## System

| Keys | Action | i3 |
|---|---|---|
| `⌥ d` | Spotlight | `$mod+d` (rofi drun) |
| `⌥ ⇧ Esc` | lock screen | `$mod+Shift+Escape` (blur-lock) |
| `⌥ ⇧ c` | reload aerospace config | `$mod+Shift+c` |

`⌥ d` is **not** an aerospace binding. Spotlight itself is moved onto `⌥ d` via
macOS symbolic hotkey 64. AeroSpace can only run shell commands, and
synthesizing `Cmd+Space` from an `alt-` binding sends `Cmd+⌥+Space` — Option is
still physically held — which is the Finder search window, not Spotlight.

Consequence: **`Cmd+Space` no longer opens Spotlight.** One hotkey ID holds one
chord.

## tmux session jumps

Each switches to workspace 2, then attaches the session, creating it if absent.
Not from i3 — mac-side additions.

| Keys | Session |
|---|---|
| `⌥ s` | settings |
| `⌥ n` | notes |
| `⌥ a` | agents |
| `⌥ t` | tunnels |
| `⌥ c` | v-control-center |
| `⌥ y` | v-web |
| `⌥ u` | v-backend |
| `⌥ i` | v-apple |
| `⌥ o` | v-android |
| `⌥ p` | v-hoover |
| `⌥ ⇧ d` | v-psql |

`⌥ ⇧ d` rather than `⌥ d`, which went to Spotlight for i3 parity.

tmux prefix is `Ctrl+Space` (`~/.dotfiles/.tmux.conf`).

## Disabled macOS hotkeys

Set in `setup_macos_hotkeys()`. Only the ones that actually stole a key.

| ID | macOS default | Why |
|---|---|---|
| 60 | select previous input source (`Ctrl+Space`) | eats the tmux prefix |
| 61 | select next input source | same chord family |
| 164 | Dictation (double-tap `Ctrl`) | tmux prefix double-taps Ctrl constantly |

## Known trade-offs

- **`⌥ ←` / `⌥ →` no longer move the cursor by word.** macOS uses Option+arrow
  for word-wise navigation in every text field; AeroSpace grabs it globally.
  `⌥ h` / `⌥ l` do the same window job, so deleting the four `alt-<arrow>` focus
  lines gets word-jump back.
- **`Cmd+Space` is no longer Spotlight** — see System above.
- The Spotlight rebind may need a logout to take effect. The hotkey *disables*
  apply immediately via `activateSettings -u`.

## Not ported from i3

| i3 | Why not |
|---|---|
| `$mod+space` focus tiling/floating toggle | AeroSpace doesn't support it — redundant in its model |
| `$mod+t` rofi window switcher | `⌥ t` is the tunnels session; tmux covers terminal switching |
| `$mod+Shift+e` powermenu | no equivalent |
| `$mod+Shift+n` empty workspace | no aerospace command |
| `$mod+Shift+r` restart i3 | `⌥ ⇧ c` reload covers it |
| `$mod+Shift+p` power profiles | Linux-only |
| `F1` keyhint | this file replaces it |
| volume / brightness / media keys | Mac hardware keys already do it |
| `$mod+Ctrl+Shift+3` screenshot | `Cmd ⇧ 3` / `Cmd ⇧ 4` native |
